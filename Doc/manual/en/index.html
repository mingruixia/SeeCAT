SeeCAT is a MATLAB toolbox for brain functional connectivity analysis of resting-state functional MRI. It takes a study from DICOM files or a BIDS dataset through preprocessing, quality control, connectivity measures and multi-site harmonisation to group statistics and figures, in one window or from scripts. This manual describes version 2.0: what each part does, how it does it, every option, the files it reads and writes, and worked examples on real data.

1 Introduction

1.1 What SeeCAT does

SeeCAT covers the whole path of a resting-state study:

  • Import to BIDS: puts DICOM folders (converted with the bundled dcm2niix) or NIfTI images (scanner and platform exports with sidecars, or older .nii/.img data) in any common layout into a BIDS dataset. It finds subjects and sessions, names task runs, field maps and single-band references, and shows every name for correction before writing.
  • Data check: lists every BOLD run with its volumes, TR and head motion.
  • Preprocessing: dummy-scan removal, slice timing, realignment, coregistration, unified segmentation, normalisation to MNI space, nuisance regression with band-pass filtering, handling of high-motion frames, smoothing; MRIQC image quality metrics, an HTML quality report per run and per study, and optional VBM maps.
  • fMRIPrep denoising: the same denoising, censoring and smoothing applied to fMRIPrep outputs.
  • Quality control: rules suggest which runs to exclude (motion, coverage, registration), image quality outliers are flagged per site, and a table lets you confirm each decision. Later steps leave excluded runs out.
  • Seed FC: seed-based functional connectivity from spheres or masks.
  • Degree: voxel-wise degree centrality and strength.
  • Gradients: connectivity gradients by diffusion map embedding, aligned across runs.
  • Harmonize: removes site and scanner effects from per-subject maps with ComBat and related models.
  • Statistics: group GLM (one- and two-sample t tests, paired tests, one-way and repeated-measures ANOVA, regression, custom designs) with covariates, random field theory and FDR correction as in SPM, or TFCE with permutations.
  • Viewer: slices, thresholds, cluster tables with atlas labels, mosaics, time series and surfaces.

Everything the window does is a configuration (a MATLAB struct, saved as JSON) passed to seecat.run, so every analysis can be repeated from a script.

1.2 What is new in 2.0

  • A rewrite: SeeCAT needs only SPM, and works on BIDS data instead of the FunImgARW… folder layout of 1.x.
  • Inputs are BIDS datasets and outputs follow BIDS-derivatives naming, so results can be read by other tools and other tools' results (fMRIPrep) can be read by SeeCAT.
  • New: DICOM conversion, fMRIPrep input, MRIQC-style quality metrics, quality-control exclusions, connectivity gradients, multi-site harmonisation, TFCE, VBM maps, parallel processing that sizes itself to the computer's memory, and a new viewer.
  • Steps resume after an interruption, and finished work with unchanged settings is skipped.

2.4 Two ways to work

The window (SeeCAT) has a page per step. Each page builds a configuration; Run starts it in a separate MATLAB process so the window stays responsive, and Save writes the configuration as a JSON file.

Scripts use the same configurations:

cfg = seecat.config('prep');                 % every option at its default
cfg.bids_dir  = 'D:/study/bids';
cfg.subjects  = {'01', '02'};                 % empty = all
cfg.n_workers = 'auto';
seecat.run(cfg);                             % writes D:/study/bids/derivatives/seecat

seecat.run('my_prep.json');                  % a configuration saved from the window

Chapter 8 lists the batch functions and complete scripts.

3 Concepts

3.1 BIDS and BIDS-derivatives

SeeCAT reads raw data organised in the Brain Imaging Data Structure and writes its results as BIDS-derivatives. A raw dataset looks like this:

bids/
  dataset_description.json
  participants.tsv                  participant_id, and columns such as group, age, sex, site
  sub-01/
    anat/sub-01_T1w.nii.gz (+ .json)
    func/sub-01_task-rest_bold.nii.gz
         sub-01_task-rest_bold.json  RepetitionTime, SliceTiming, ...

File names are made of entities, key-value pairs separated by underscores, and end with a suffix (bold, T1w, mask, connectivity, ...). SeeCAT's outputs keep the entities of their source and add their own:

EntityMeaningExample
sub, ses, task, acq, runsubject, session, task, acquisition, run of the sourcesub-01_ses-1_task-rest_run-2
space, restemplate space and resolution labelspace-IXI549Space_res-3
descwhich variant of the datadesc-preproc, desc-denoised, desc-denoisedSm6, desc-PCC
statwhich statistic a map holdsstat-r, stat-z, stat-t, stat-p
labeltissue of a probability maplabel-GM_probseg

Every image comes with a JSON sidecar that records how it was made (sources, settings, frames used).

3.2 Spaces and templates

SeeCAT's own preprocessing normalises to SPM's template space, IXI549Space (the space of SPM's tissue probability maps, close to MNI152). Outputs are written at the chosen voxel size (3 mm by default) over SPM's bounding box [-90 -126 -72; 90 90 108]. fMRIPrep outputs stay in their space, usually MNI152NLin2009cAsym. The templates folder holds brain, GM, WM and CSF masks at 2 and 3 mm, made from SPM's TPMs, and underlays for the viewer (ch2, ch2better, ICBM152 2009c).

3.3 Units, resuming and skipping

Each pipeline splits its work into units: one BOLD run for Preprocessing, fMRIPrep denoising, Seed FC and Degree; one unit for a group step (Gradients, Harmonize, Statistics). When a unit finishes, SeeCAT records its settings. Running again:

  • skips a unit that finished with the same settings (Overwrite runs it again);
  • runs a unit again when its settings changed, after deleting the files it wrote before;
  • resumes a unit that failed at the step where it stopped, from its work folder;
  • never leaves a failed unit's partial outputs among the derivatives.

A failed unit does not stop the others; the summary table and the logs say what failed and why.

3.4 Logs, configurations and summaries

Every run writes, under <output>/logs: the configuration as JSON (<pipeline>_<time>_config.json), a main log, one log per unit, and a list of every file each unit wrote. <output>/reports/<pipeline>_<time>_summary.tsv has one row per unit: status, time, message and the unit's key results (frames kept, mean FD, ...).

3.5 Parallel processing and memory

The Parallel workers option of each page sets how many units run at the same time:

  • auto (default): as many as fit in memory. SeeCAT estimates the memory one unit needs (from the size of the largest run, the brain mask, the node count of Gradients, the maps of Statistics), adds about 1 GB per worker, keeps what the main MATLAB needs, and uses at most 85 % of the free memory, one worker per core and one per unit. The log states the estimate and the choice. With only one unit (Harmonize, Statistics without TFCE), with too little memory for two workers, or without the Parallel Computing Toolbox, it runs one after another without a pool;
  • 0: one after another, e.g. to leave the computer free for other work;
  • a number: at most that many workers.

Each worker is given its share of the computer's cores as threads (e.g. 5 workers on 32 cores get 6 threads each), so matrix work keeps its speed. For Gradients and TFCE, which are one unit, the workers share the runs or the permutations of that unit. If a pool fails to start, SeeCAT tries once more with half the workers and only then runs one after another, and the log says why.

3.6 Quality-control exclusions

After Preprocessing or fMRIPrep denoising, the group report writes reports/qc_exclusions.tsv, a list of every run (and T1w image) with a decision: keep or exclude. Rules suggest exclusions; on the QC reports page you confirm or change them. Seed FC, Degree, Gradients, Harmonize and Statistics then leave excluded runs out (their option Leave out QC exclusions, on by default) and list them in the log. Chapter 6.5 describes the rules.

3.7 participants.tsv

Group information comes from participants.tsv of the BIDS dataset: the group of each subject, age, sex, site, scores. Statistics and Harmonize read it next to the derivatives, two folders up (bids/derivatives/seecat → bids), or from the dataset named in the derivatives' dataset_description.json; a different file can be chosen. Columns with numbers are used as numbers, text columns as categories. Tissue volumes from Preprocessing (gm_ml, wm_ml, csf_ml, tiv_ml, in reports/anat_volumes.tsv) can be used as if they were columns of participants.tsv.

4 The main window

4.1 Layout

  • Pages (left) in three groups: PREPARE (Import to BIDS, Preprocessing, fMRIPrep denoising), ANALYSE (Seed FC, Degree, Gradients, Harmonize, Statistics) and RESULTS (Viewer, Data check, QC reports). Manual opens this document, About shows the version.
  • Options (centre), in cards such as Input, Preprocessing, Denoising. The tabs above jump to a card. Show advanced options adds the options most studies keep at their defaults.
  • Description (right): click the i icon of an option, or edit it, to read what it does, with examples, its default and its batch field name. Hovering over an option shows a short tooltip.
  • Run panel (right, bottom): Run, Stop, the progress of the units, and the state (Ready, Running, Finished, Failed).
  • Drawer (bottom): the Log and the Summary table of the last run; the arrow opens and closes it.
  • Load and Save (top right): read or write the page's configuration as JSON. A configuration saved here runs unchanged with seecat.run.

4.2 Running

Run checks every option first and lists all problems at once (an empty required folder, a value out of range). The pipeline then runs in a separate MATLAB process: the window stays usable, the log streams into the drawer, and Stop ends the process (units that finished keep their outputs; the unit that was interrupted resumes next time). When the run ends, the Summary tab of the drawer shows the run's table (one row per unit, as in reports/<pipeline>_<time>_summary.tsv); each unit's own log is in logs/<pipeline>_<time>/.

6 The modules

Each section below describes one page: what it is for, how it works, every option (the tables are generated from the software, so they show exactly what the window offers), what it reads and writes, and how to run it from a script. Options marked advanced appear after ticking Show advanced options. 6.1 Import to BIDS

Puts the data you have into a BIDS dataset. Point it at a folder of DICOM files, which are converted with dcm2niix (bundled), or of NIfTI images. NIfTI images may be scanner or imaging-platform exports with .json sidecars, or older .nii, .nii.gz or .img data without them; they are organised as they are. SeeCAT finds the subjects, visits and images and proposes a BIDS name for every image. You can correct the names before anything is written. The source folder is only read.

Working with it

  1. Give the Source folder and the BIDS folder. The BIDS folder must lie outside the source folder. Leave Subject, Session and Rules empty to begin with.
  2. Preview names writes nothing. The Log shows the layout it recognised (for example subjects from folder names at level 1 (e.g. sub173_zhangsan → sub-173)). The Summary table lists every image with its subject, session, series, description, source, proposed bids name and a note: how it was named, or why it is left out.
  3. Check the bids column. To change a name, edit the path. To leave an image out, empty it. A single-band reference follows its BOLD run when the run is renamed or left out.
  4. Convert uses the table as it is shown.
  5. Save as rules turns the checked names into a rules file and puts it in Rules. Preview and Convert then name every subject's images the same way; run them on the whole study.

How subjects, sessions and images are found

  1. DICOM or NIfTI. A folder with NIfTI images below it (outside derivatives) is imported from them; otherwise its DICOM files are converted.
  2. Subjects, NIfTI. SeeCAT tries these in order:
    1. sub-<label> folders.
    2. The shallowest level of folders whose names all look like IDs. Such names contain a digit and are not dates, session names or series folders such as 07_rest. This covers one folder per subject (S001/…), modality folders with subject folders inside (FunRaw/S001, T1Raw/S001) and exports by visit and series (sub173_zhangsan/2026-10-13T11_09_18/functional/07_…).
    3. IDs at the start of the file names (S01_rest.nii).
    4. The PatientID of the sidecars.
    5. The source folder's own name.
    The label keeps the ID and drops a name written after it (sub173_zhangsan → 173, S_001 → S001). For any other layout, 'subject_pattern' takes a regular expression with one token, e.g. 'Subj_(\d+)'.
  3. Subjects, DICOM. SeeCAT reads the first and last file of every folder with DICOM files. Folders with the same PatientID are one subject, named after the folder that holds all of that person's folders and no one else's. When IDs are missing or anonymised, the folder tree decides. A folder whose first and last files belong to different people is an error.
  4. Sessions. Folders named ses-<label>, pre, post, baseline, followup, visit1, v1 or t1 give the session. Otherwise images are grouped into scanning visits by the study in the sidecars or headers, or by date folders. A subject with one visit gets no session folder. Several visits become ses-1, ses-2, … by date; the assignment is kept in code/seecat/from_dicom_sessions.tsv, so a later visit gets the next number.
  5. Names. The first rule that matches an image names it (see Rules below). The default rules take a 3D T1-weighted image (MPRAGE, SPGR, BRAVO, …) as anat/…_T1w and resting-state BOLD (rest, rsfMRI, or RS as a word) as …_task-rest_bold. Images that no rule names are recognised as follows:
    • Task BOLD: 2D EPI with 20 or more volumes. The task comes from the series name without its trailing number, which becomes the run: Math_AI_trust3 → task-mathaitrust_run-3. Scanner words such as BOLD, EPI or MB are dropped from the name.
    • Field maps: series named fieldmap, fmap, B0 map, topup or SE-EPI. Gradient-echo field maps become magnitude1, magnitude2 and phasediff, with EchoTime1 and EchoTime2 taken from the magnitudes. Spin-echo EPI field maps become epi with dir-AP, PA, … from the series name or the phase-encoding direction.
    • Single-band references (SBRef, …_SB1, one volume) become the sbref of the next BOLD run of the visit with the same slice grid.
    • Diffusion: images with .bval/.bvec become dwi.
    • Left out, with the reason in the note: localizers, phase and derived images, and the copy of a T1w without distortion correction (ImageType ND) when the corrected one is there. Anything else is reported, not copied.
  6. Runs, echoes and IntendedFor. Several series with the same name in a session get run-1, run-2, … in series order. The echoes of one series get echo-1, … A field map set is used by the BOLD runs (and their sbrefs) acquired after it and before the next set; they are written to its IntendedFor as bids:: paths.
  7. Images without a sidecar get their description from the folders and the file name, and the volume count and TR from the header. The 'tr' option gives the TR when the header has none. Numbered 3D images (f0001.nii, f0002.nii, …: ten or more in one folder) are one run, written as one 4D image, when only the number at the end of the name changes. S01_rest_0001.nii and S02_rest_0001.nii, or run1_vol0001.nii and run2_vol0001.nii, belong to different runs. A series whose numbers have gaps, or whose images differ in grid, orientation or TR, is not merged, and a warning says why: put each run's volumes in a folder of their own, or merge them into a 4D image first. Analyze .img/.hdr pairs are written as NIfTI.
  8. Writing.
    • Images go to sub-<label>/[ses-<label>/]anat|func|fmap|dwi as .nii.gz with their sidecars.
    • Sidecars are copied without the person's name, ID, birth date and other identifying fields. The subject's name is also taken out of the text fields that are kept (SeriesDescription, ProtocolName, nested fields) and out of the descriptions of images without a sidecar. SeeCAT knows the name from PatientName, from the words after the ID in the subject's folder (sub173_zhangsan), and from the words right after the ID at the start of a file name that no other subject's files have (sub173_zhangsan_rest.nii next to sub174_lisi_rest.nii). Such a file-name word may also be a task (S01_memory_bold.nii next to S02_motor_bold.nii): it is still kept out of the dataset, and when no other word gives the task, the run is named task-unknown with the note task not known, not guessed as rest. Set the task in the bids column before converting. A name written another way (zhangsan_173, or glued to other words) is not recognised, and other free text is kept as it is: check the report and the sidecars before sharing the dataset. participants.tsv gets the subject, with sex and age at the scan when the sidecars give them.
    • dataset_description.json is written if missing.
    • Images already in the dataset are kept, so importing again only adds what is missing.
    • A table of every image and what happened to it is written to code/seecat/from_nifti_sub-<label>.tsv (or from_dicom_…). In this table the subject's folder, or the ID at the start of a file name, is shown as sub-<label>, and the names found as above are left out of the paths and descriptions. The original paths appear only in the Preview names table of the window and in the table that seecat.bids.from_nifti returns; they are not written to the dataset.

In scripts, a few more options are available:

  • 'dryrun', true returns the plan without writing.
  • 'names', P uses an edited plan (a table or TSV file).
  • 'auto', false names only what rules name.
  • 'tr', 2 gives the TR for BOLD without one.
  • 'link', true makes hard links instead of copies for .nii.gz images on the same drive. This saves space, but the dataset and the export then share those files.
  • 'subject_pattern' finds the subject label in the path with a regular expression.

A rule matches sidecar fields with regular expressions (case-insensitive) and gives datatype, suffix and entities, or "skip": true to leave the image out. Besides the sidecar fields, Path (where the image is in the source folder) and Volumes can be matched. The first rule that matches wins.

6.3 Preprocessing

Preprocesses every BOLD run of a BIDS dataset with SPM and writes analysis-ready data to derivatives/seecat. Each run is a unit; its T1w (from the same session if there is one) is used for registration and segmentation.

Steps

  1. Input. The run and its T1w are copied into the work folder. Leading non-steady-state volumes are removed: with dummy_scans = auto, leading volumes whose mean brain intensity is a robust outlier (z > 3.5 against the median and MAD of the run, within the first 20) are dropped; volumes the scanner already discarded are not counted again.
  2. Slice timing (SPM). The slice acquisition times come from SliceTiming in the sidecar (seconds), so sequential, interleaved and multiband orders are all handled; the reference is the middle of the TR unless set. The times are read along SliceEncodingDirection (k when absent; k- is reversed to voxel order). Slices along the first or second voxel axis (i, j) are not supported and stop the run with an error; reorient such images, or turn slice timing off.
  3. Realignment (SPM). Two passes, to the first volume and then to the mean. The six motion parameters go to the confounds table; the data are not resampled here.
  4. Coregistration. The T1w is registered to the mean EPI by normalised mutual information (only its header changes).
  5. Segmentation. SPM unified segmentation of the T1w with SPM's tissue probability maps gives native GM, WM and CSF maps, a bias-corrected T1w and the deformation to IXI549Space. Without a T1w (normalise.method = epi) the mean EPI is segmented instead.
  6. Nuisance masks. WM (p > 0.99) and CSF (p > 0.95) masks in the subject's own space, eroded by a 2 mm ball, so they keep away from grey matter; they are resampled to the output grid.
  7. Normalisation. The deformation is applied once to the BOLD data (4th-degree B-spline; the only resampling of the data) and to the tissue maps, at the chosen voxel size over SPM's bounding box.
  8. Masks in output space: brain = GM + WM + CSF > 0.5, inside the field of view in every frame.
  9. Confounds. A table with fMRIPrep's column names: 24 motion regressors (6 parameters, their derivatives and squares; Friston 1996), framewise displacement (Power 2012), the mean signals of brain (global_signal), WM and CSF, aCompCor components of WM and CSF (computed on good frames), one motion_outlier_XX column per flagged frame and a censor column.
  10. IQMs (optional, on by default): MRIQC image quality metrics of the raw BOLD and T1w; see 6.5.
  11. Denoising. One linear model per voxel: polynomial trend (order 1) + the chosen regressors, with data and regressors band-passed by the same filter, fitted on the good frames. High-motion frames are first filled in from the good frames (spectral interpolation) so that filtering does not spread them, then left out of the fit and marked for later steps. The voxel mean is added back. Output: desc-denoised.
  12. Smoothing (optional): Gaussian kernel of the chosen FWHM; output desc-denoisedSm6. The unsmoothed series is kept.
  13. Outputs and a QC report per run; when all runs have finished, the group report and the exclusion list.
Why denoise before smoothing, and why filter regressors too. Regressing nuisance signals from smoothed data mixes signals of neighbouring tissue; band-passing the data but not the regressors reintroduces removed signal (Hallquist et al. 2013; Lindquist et al. 2019). SeeCAT filters both and fits them together. High-motion frames are interpolated before filtering because a spike would otherwise spread over its neighbours; the interpolated frames are never used by later statistics (Power et al. 2014).

6.5 Quality control

Quality control runs inside Preprocessing and fMRIPrep denoising; the QC reports page is where you review it and decide which runs are used.

The run report

Each run gets sub-*/…_desc-qc_report.html with:

  • a summary: frames, dummy scans, mean and largest FD, flagged frames, minutes kept, tSNR, the correlation of FD with DVARS before and after denoising (a good denoising brings it close to 0), largest translation and rotation, coverage;
  • head motion: FD over time with the threshold and flagged frames shaded, translations and rotations;

6.7 Degree

Voxel-wise degree centrality. Every voxel of the mask is a node of the correlation network of a run (frames kept after censoring). The binary degree of a voxel counts its connections whose correlation reaches the threshold; the weighted degree (strength) sums their r values. As in SeeCAT 1.0: correlations from z-scored series, the sign rule applied (absolute: |r|; negative: −r), values below the threshold set to 0. Optionally connections shorter than a distance are ignored, or split into distance bins (short- and long-range degree). Which voxels form the network follows Mask and Mask mode (see Masks under Seed FC). Maps are written raw and z-scored within the mask (over the voxels with signal), and smoothed afterwards if asked (the network is built from unsmoothed data).

6.8 Gradients

Connectivity gradients (Margulies et al. 2016): the main axes along which connectivity profiles change across the cortex, the first usually running from sensory and motor cortex to the default-mode network. For each run:

  1. the node series: the mean of the run's brain-mask voxels in each node (with Mask mode, the group-mask voxels, or the mask or atlas voxels with signal; see Masks under Seed FC) (voxels of a coarser MNI grid, or parcels of an atlas), frames kept after censoring;
  2. the connectivity matrix: Pearson r between nodes;
  3. each row keeps its strongest 10 % (sparsity 0.9) and the rest is set to 0;
  4. the affinity between rows: normalised angle (1 − angle/π of their cosine similarity) or cosine;
  5. diffusion map embedding with α = 0.5 (Coifman & Lafon 2006) and multiscale eigenvalues λ/(1−λ), as BrainSpace (Vos de Wael et al. 2020);

then the runs are aligned (generalized Procrustes: rotations and sign flips onto a reference, the reference updated to the mean, up to 10 rounds), starting from the gradients of the group-mean connectivity matrix (default) or from the first run. SeeCAT's embedding equals the exact diffusion map; it solves the symmetric form of the problem.

6.9 Harmonize

Multi-site studies carry site and scanner differences in every map. Harmonize removes them from per-subject maps, between the measures (Seed FC, Degree, Gradients, VBM) and Statistics, while keeping the effects you will test. It writes the harmonised maps next to the originals with the desc label extended (desc-PCC → desc-PCCComBat).

B2. Why not ComBat here

Site differences in VBM are large: in 49.8% of grey-matter voxels before harmonisation (0.2% after ComBat with group, sex, age and TIV kept). It seems natural to harmonise first. We ran the same regression after each choice:

The age effect is not real, so the ComBat clusters are false positives. ComBat rescales each site's residual variance using only ten subjects per site. That makes the harmonised data look less variable than they are, and tests of the kept covariates become too liberal (Nygaard et al. 2016). Methods that only remove site means do not have this problem. With fewer than about 20 subjects per site:

  • use combat_mean or lm, or keep the maps unharmonised with site as a covariate;
  • compare any ComBat result with the unharmonised one before reporting it.

Each run needs a 21972 × 21972 connectivity matrix, so memory, not cores, set the number of workers (18). The reference is the gradient of the group-mean matrix. Each run is aligned to it, a new reference is formed from the mean of the aligned runs, and this repeats until the reference no longer changes.

group/gradientsVox4/gradientsVox4_lambdas.tsv gives, per run:

  • the eigenvalues;
  • the variance explained by gradient 1: 0.18 to 0.31, median 0.24;
  • the correlation of the run's aligned gradient 1 with the reference: 0.43 to 0.69, median 0.58.

A run with a much lower correlation than the others deserves a look at its QC report. The per-run maps (desc-grad1Vox4 … grad3Vox4) can be harmonised and tested like any other map.

10.2 Common questions

A subject failed. Do I have to run everything again?

No. Run the same configuration again: finished subjects are skipped and the failed one resumes at the step where it stopped. The unit's log (logs/<pipeline>_<time>/<unit>.log) gives the reason.

I changed an option. What is recomputed?

Every unit whose result depends on it. Changing only Parallel workers or Keep work files recomputes nothing; ticking Overwrite recomputes every unit and clears its work folder. A finished unit is also run again when its inputs changed, when SeeCAT itself changed, or when one of its outputs was deleted; the log says why. Inputs are every file the unit reads, including the files named in the options (seed and ROI images, masks, atlases, image covariates, the participants table), the set of maps selected, the participant values and the runs excluded or restored by QC. A file named by a relative path (seed.nii, ./rois/seed.nii) is the file in MATLAB's current folder, as when it is read; text without a file extension, such as gm or auto, is a keyword. A file up to 64 MB is compared by its contents, a larger one (a BOLD series) by its size and date. SeeCAT itself is the code that computes the results and the bundled templates: after an update, finished units are computed again with the new code. Each run checks the names, sizes and dates of the code files, so this also holds when the code changes while MATLAB is open, without a restart. Files outside these, for example an SPM installed elsewhere, are not followed; tick Overwrite after changing them.

Can I write the results into the input folder, or run SeeCAT twice at once?

The output folder may not be the BIDS folder or the fMRIPrep folder; SeeCAT refuses it before writing anything. In every other case a unit that would write over one of its own input files stops with an error and leaves the file as it is. Two SeeCAT sessions may work in the same output folder at the same time on different units (for example different subjects); a unit that another session is computing fails with a message naming that session, and is computed when you run the configuration again. If MATLAB was closed while a unit ran, its lock (logs/locks/) is removed by the next run on the same computer.

Seed FC says "no desc-denoised bold" or finds no runs.

Check that the derivatives folder is the output of Preprocessing or fMRIPrep denoising and that Denoise was on. If the folder holds runs in more than one space, set Space; with several tasks, set Task. If every run is excluded by QC, check the QC reports page.

Statistics finds several maps per subject.

The map fields must pick exactly one map per subject (two for paired designs). Add Space, Task or Other (e.g. run=1) until the line below the fields counts one map per subject.

Where are age, sex and group taken from?

From participants.tsv of the BIDS dataset (see 3.7). Values that are empty or n/a drop that subject from the analysis that uses the column, and the log lists it.

Should I smooth before Seed FC?

The default input is the unsmoothed desc-denoised; use denoisedSm6 to follow studies that correlate smoothed data. Degree and Gradients should use unsmoothed data; Degree smooths its maps afterwards.

Why harmonize, and when not?

Harmonize when maps from several sites or scanners enter one analysis and the sites have enough subjects (ComBat works best with 10 or more per site). Keep every effect you will test among the covariates. With a single site, skip it.

How do I report the quality control?

The group report gives the rules, the runs excluded and why; reports/qc_exclusions.tsv and prep_qc.tsv hold the numbers. Report the exclusion rules, how many runs were excluded per group and site, and mean FD per group.

The window does not respond during a run.

It should: runs happen in a separate MATLAB process. If MATLAB itself is busy (e.g. a long command in the command window), the window waits for it.

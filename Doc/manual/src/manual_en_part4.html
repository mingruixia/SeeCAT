Batch scripting

Everything in the window is available from MATLAB code. A pipeline is configured by a struct and run by seecat.run; the window's Save button writes the same struct as JSON.

A complete study

The scripts of chapter 7, in one file. Each seecat.run call can be run on its own; finished units are skipped when run again.

bids = 'D:/data/test_seecat/DIDA/bids2';
out  = 'D:/data/test_seecat/DIDA/manual_run/derivatives/seecat';

% 1. Preprocessing with image quality metrics and VBM maps
cfg = seecat.config('prep');
cfg.bids_dir   = bids;
cfg.output_dir = out;
cfg.vbm.enable = true;
cfg.n_workers  = 'auto';
seecat.run(cfg);
% ... review reports/prep_qc.html and the QC reports page ...

% 2. Seed FC
cfg = seecat.config('fc');
cfg.input_dir = out;
cfg.seeds = struct('name', {'PCC', 'mPFC'}, 'center', {[0 -53 26], [0 52 -6]}, ...
                   'radius', {6, 6}, 'file', {'', ''});
cfg.n_workers = 'auto';
seecat.run(cfg);

% 3. Degree and gradients
cfg = seecat.config('degree');   cfg.input_dir = out;   cfg.n_workers = 'auto';   seecat.run(cfg);
cfg = seecat.config('gradient'); cfg.input_dir = out;   cfg.n_workers = 'auto';   seecat.run(cfg);

% 4. Harmonize the PCC maps across the three sites
cfg = seecat.config('harmonize');
cfg.input_dir  = out;
cfg.maps       = struct('desc', 'PCC', 'stat', 'z');
cfg.site       = 'site';
cfg.covariates = {'group', 'sex', 'age'};
seecat.run(cfg);                                  % writes desc-PCCComBat maps

% 5. One-sample t test in the HC group, with TFCE
P  = seecat.io.read_tsv(fullfile(bids, 'participants.tsv'));
hc = erase(P.participant_id(strcmp(P.group, 'HC')), 'sub-')';
cfg = seecat.config('stat');
cfg.name      = 'PCConeSampleHC';
cfg.input_dir = out;
cfg.maps      = struct('desc', 'PCCComBat', 'stat', 'z');
cfg.design    = 'one_sample';
cfg.subjects  = hc;
cfg.inference = {'cluster_fwe', 'tfce_fwe'};
cfg.n_workers = 'auto';
seecat.run(cfg);

% 6. VBM: grey matter and age, unharmonised maps with site as a covariate
cfg = seecat.config('stat');
cfg.name       = 'VBMage';
cfg.input_dir  = out;
cfg.maps       = struct('desc', 'modulatedSm8', 'label', 'GM', 'suffix', 'probseg');
cfg.design     = 'regression';
cfg.regressors = {'age'};
cfg.covariates = {'sex', 'tiv_ml', 'site'};
cfg.mask       = 'gm';
seecat.run(cfg);

seecat.viewer(fullfile(out, 'group', 'PCConeSampleHC', 'PCConeSampleHC_contrast-pos_stat-t_statmap.nii.gz'));

Configuration files

A configuration file is the struct as JSON. Only the options you change need to be in it; the others take their defaults. Numbers with Inf are written as text ("[0 75 Inf]") and read back as numbers.

{
  "pipeline": "stat",
  "name": "PCCtwoSample",
  "input_dir": "D:/data/test_seecat/DIDA/manual_run/derivatives/seecat",
  "maps": {"desc": "PCCComBat", "stat": "z"},
  "design": "two_sample",
  "factor": "group",
  "levels": ["HC", "MDD"],
  "covariates": ["age", "sex"]
}

Run several configurations in sequence:

for f = {'prep.json', 'fc.json', 'harmonize.json', 'stat.json'}
    seecat.run(fullfile('D:/study/configs', f{1}));
end

Running on a server

Without a display, start MATLAB with -batch:

matlab -batch "addpath('/opt/spm'); addpath('/opt/SeeCAT/SeeCAT'); seecat.run('/data/configs/prep.json')"

Logs are written as the run goes (<output>/logs), so progress can be followed with tail -f.

JSON sidecars

Each image's sidecar describes how it was made. Common fields: Sources (the files it came from: BIDS URIs such as bids:raw:sub-01/func/… for the per-run outputs; Harmonize and Statistics list the paths of their input maps), Software, and step-specific fields, for example FramesUsed, FramesTotal and Seed (Seed FC); Threshold, Sign, Measure (Degree); Lambdas, VarianceExplained, Alignment (Gradients); Harmonization, Site, KeptEffects (Harmonize); DegreesOfFreedom, FWHMmm, Resels, Contrast, Inference (Statistics).

Common questions

A subject failed. Do I have to run everything again?

No. Run the same configuration again: finished subjects are skipped and the failed one resumes at the step where it stopped. The unit's log (logs/<pipeline>_<time>/<unit>.log) gives the reason.

I changed an option. What is recomputed?

Every unit whose result depends on it. Changing only Parallel workers or Keep work files recomputes nothing; ticking Overwrite recomputes every unit and clears its work folder. A finished unit is also run again when its inputs changed, when SeeCAT itself changed, or when one of its outputs was deleted; the log says why. Inputs are every file the unit reads, including the files named in the options (seed and ROI images, masks, atlases, image covariates, the participants table), the set of maps selected, the participant values and the runs excluded or restored by QC. A file up to 64 MB is compared by its contents, a larger one (a BOLD series) by its size and date. SeeCAT itself is the code that computes the results and the bundled templates: after an update, finished units are computed again with the new code. Files outside these, for example an SPM installed elsewhere, are not followed; tick Overwrite after changing them.

Can I write the results into the input folder, or run SeeCAT twice at once?

The output folder may not be the BIDS folder or the fMRIPrep folder; SeeCAT refuses it before writing anything. In every other case a unit that would write over one of its own input files stops with an error and leaves the file as it is. Two SeeCAT sessions may work in the same output folder at the same time on different units (for example different subjects); a unit that another session is computing fails with a message naming that session, and is computed when you run the configuration again. If MATLAB was closed while a unit ran, its lock (logs/locks/) is removed by the next run on the same computer.

Seed FC says "no desc-denoised bold" or finds no runs.

Check that the derivatives folder is the output of Preprocessing or fMRIPrep denoising and that Denoise was on. If the folder holds runs in more than one space, set Space; with several tasks, set Task. If every run is excluded by QC, check the QC reports page.

Statistics finds several maps per subject.

The map fields must pick exactly one map per subject (two for paired designs). Add Space, Task or Other (e.g. run=1) until the line below the fields counts one map per subject.

Where are age, sex and group taken from?

From participants.tsv of the BIDS dataset (see 3.7). Values that are empty or n/a drop that subject from the analysis that uses the column, and the log lists it.

Should I smooth before Seed FC?

The default input is the unsmoothed desc-denoised; use denoisedSm6 to follow studies that correlate smoothed data. Degree and Gradients should use unsmoothed data; Degree smooths its maps afterwards.

Why harmonize, and when not?

Harmonize when maps from several sites or scanners enter one analysis and the sites have enough subjects (ComBat works best with 10 or more per site). Keep every effect you will test among the covariates. With a single site, skip it.

How do I report the quality control?

The group report gives the rules, the runs excluded and why; reports/qc_exclusions.tsv and prep_qc.tsv hold the numbers. Report the exclusion rules, how many runs were excluded per group and site, and mean FD per group.

The window does not respond during a run.

It should: runs happen in a separate MATLAB process. If MATLAB itself is busy (e.g. a long command in the command window), the window waits for it.

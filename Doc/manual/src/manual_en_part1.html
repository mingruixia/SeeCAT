SeeCAT (Seed-based Connectivity Analysis Toolbox) is a MATLAB toolbox for resting-state functional MRI. It takes a study from DICOM files or a BIDS dataset through preprocessing, quality control, connectivity measures and multi-site harmonisation to group statistics and figures, in one window or from scripts. This manual describes version 2.0: what each part does, how it does it, every option, the files it reads and writes, and worked examples on real data.

Introduction

What SeeCAT does

SeeCAT covers the whole path of a resting-state study:

  • DICOM to BIDS: converts DICOM folders in any common layout into a BIDS dataset with dcm2niix (bundled), finding subjects and sessions by itself.
  • Data check: lists every BOLD run with its volumes, TR and head motion.
  • Preprocessing: dummy-scan removal, slice timing, realignment, coregistration, unified segmentation, normalisation to MNI space, nuisance regression with band-pass filtering, handling of high-motion frames, smoothing; MRIQC image quality metrics, an HTML quality report per run and per study, and optional VBM maps.
  • fMRIPrep denoising: the same denoising, censoring and smoothing applied to fMRIPrep outputs.
  • Quality control: rules suggest which runs to exclude (motion, coverage, registration), image quality outliers are flagged per site, and a table lets you confirm each decision. Later steps leave excluded runs out.
  • Seed FC: seed-based functional connectivity from spheres or masks.
  • Degree: voxel-wise degree centrality and strength.
  • Gradients: connectivity gradients by diffusion map embedding, aligned across runs.
  • Harmonize: removes site and scanner effects from per-subject maps with ComBat and related models.
  • Statistics: group GLM (one- and two-sample t tests, paired tests, one-way and repeated-measures ANOVA, regression, custom designs) with covariates, random field theory and FDR correction as in SPM, or TFCE with permutations.
  • Viewer: slices, thresholds, cluster tables with atlas labels, mosaics, time series and surfaces.

Everything the window does is a configuration (a MATLAB struct, saved as JSON) passed to seecat.run, so every analysis can be repeated from a script.

What is new in 2.0

  • A rewrite: SeeCAT needs only SPM. It no longer uses DPABI or the FunImgARW… folder layout of 1.x.
  • Inputs are BIDS datasets and outputs follow BIDS-derivatives naming, so results can be read by other tools and other tools' results (fMRIPrep) can be read by SeeCAT.
  • New: DICOM conversion, fMRIPrep input, MRIQC-style quality metrics, quality-control exclusions, connectivity gradients, multi-site harmonisation, TFCE, VBM maps, parallel processing that sizes itself to the computer's memory, and a new viewer.
  • Steps resume after an interruption, and finished work with unchanged settings is skipped.

Two ways to work

The window (SeeCAT) has a page per step. Each page builds a configuration; Run starts it in a separate MATLAB process so the window stays responsive, and Save writes the configuration as a JSON file.

Scripts use the same configurations:

cfg = seecat.config('prep');                 % every option at its default
cfg.bids_dir  = 'D:/study/bids';
cfg.subjects  = {'01', '02'};                 % empty = all
cfg.n_workers = 'auto';
seecat.run(cfg);                             % writes D:/study/bids/derivatives/seecat

seecat.run('my_prep.json');                  % a configuration saved from the window

Chapter 8 lists the batch functions and complete scripts.

Concepts

BIDS and BIDS-derivatives

SeeCAT reads raw data organised in the Brain Imaging Data Structure and writes its results as BIDS-derivatives. A raw dataset looks like this:

bids/
  dataset_description.json
  participants.tsv                  participant_id, and columns such as group, age, sex, site
  sub-01/
    anat/sub-01_T1w.nii.gz (+ .json)
    func/sub-01_task-rest_bold.nii.gz
         sub-01_task-rest_bold.json  RepetitionTime, SliceTiming, ...

File names are made of entities, key-value pairs separated by underscores, and end with a suffix (bold, T1w, mask, connectivity, ...). SeeCAT's outputs keep the entities of their source and add their own:

EntityMeaningExample
sub, ses, task, acq, runsubject, session, task, acquisition, run of the sourcesub-01_ses-1_task-rest_run-2
space, restemplate space and resolution labelspace-IXI549Space_res-3
descwhich variant of the datadesc-preproc, desc-denoised, desc-denoisedSm6, desc-PCC
statwhich statistic a map holdsstat-r, stat-z, stat-t, stat-p
labeltissue of a probability maplabel-GM_probseg

Every image comes with a JSON sidecar that records how it was made (sources, settings, frames used).

Spaces and templates

SeeCAT's own preprocessing normalises to SPM's template space, IXI549Space (the space of SPM's tissue probability maps, close to MNI152). Outputs are written at the chosen voxel size (3 mm by default) over SPM's bounding box [-90 -126 -72; 90 90 108]. fMRIPrep outputs stay in their space, usually MNI152NLin2009cAsym. The templates folder holds brain, GM, WM and CSF masks at 2 and 3 mm, made from SPM's TPMs, and underlays for the viewer (ch2, ch2better, ICBM152 2009c).

Units, resuming and skipping

Each pipeline splits its work into units: one BOLD run for Preprocessing, fMRIPrep denoising, Seed FC and Degree; one unit for a group step (Gradients, Harmonize, Statistics). When a unit finishes, SeeCAT records its settings. Running again:

  • skips a unit that finished with the same settings (Overwrite runs it again);
  • runs a unit again when its settings changed, after deleting the files it wrote before;
  • resumes a unit that failed at the step where it stopped, from its work folder;
  • never leaves a failed unit's partial outputs among the derivatives.

A failed unit does not stop the others; the summary table and the logs say what failed and why.

Logs, configurations and summaries

Every run writes, under <output>/logs: the configuration as JSON (<pipeline>_<time>_config.json), a main log, one log per unit, and a list of every file each unit wrote. <output>/reports/<pipeline>_<time>_summary.tsv has one row per unit: status, time, message and the unit's key results (frames kept, mean FD, ...).

Parallel processing and memory

The Parallel workers option of each page sets how many units run at the same time:

  • auto (default): as many as fit in memory. SeeCAT estimates the memory one unit needs (from the size of the largest run, the brain mask, the node count of Gradients, the maps of Statistics), adds about 1 GB per worker, keeps what the main MATLAB needs, and uses at most 85 % of the free memory, one worker per core and one per unit. The log states the estimate and the choice. With only one unit (Harmonize, Statistics without TFCE), with too little memory for two workers, or without the Parallel Computing Toolbox, it runs one after another without a pool;
  • 0: one after another, e.g. to leave the computer free for other work;
  • a number: at most that many workers.

Each worker is given its share of the computer's cores as threads (e.g. 5 workers on 32 cores get 6 threads each), so matrix work keeps its speed. For Gradients and TFCE, which are one unit, the workers share the runs or the permutations of that unit. If a pool fails to start, SeeCAT tries once more with half the workers and only then runs one after another, and the log says why.

Quality-control exclusions

After Preprocessing or fMRIPrep denoising, the group report writes reports/qc_exclusions.tsv, a list of every run (and T1w image) with a decision: keep or exclude. Rules suggest exclusions; on the QC reports page you confirm or change them. Seed FC, Degree, Gradients, Harmonize and Statistics then leave excluded runs out (their option Leave out QC exclusions, on by default) and list them in the log. Chapter 6.5 describes the rules.

participants.tsv

Group information comes from participants.tsv of the BIDS dataset: the group of each subject, age, sex, site, scores. Statistics and Harmonize read it next to the derivatives, two folders up (bids/derivatives/seecat → bids), or from the dataset named in the derivatives' dataset_description.json; a different file can be chosen. Columns with numbers are used as numbers, text columns as categories. Tissue volumes from Preprocessing (gm_ml, wm_ml, csf_ml, tiv_ml, in reports/anat_volumes.tsv) can be used as if they were columns of participants.tsv.

The main window

Layout

  • Pages (left) in three groups: PREPARE (DICOM to BIDS, Preprocessing, fMRIPrep denoising), ANALYSE (Seed FC, Degree, Gradients, Harmonize, Statistics) and RESULTS (Viewer, Data check, QC reports). Manual opens this document, About shows the version.
  • Options (centre), in cards such as Input, Preprocessing, Denoising. The tabs above jump to a card. Show advanced options adds the options most studies keep at their defaults.
  • Description (right): click the i icon of an option, or edit it, to read what it does, with examples, its default and its batch field name. Hovering over an option shows a short tooltip.
  • Run panel (right, bottom): Run, Stop, the progress of the units, and the state (Ready, Running, Finished, Failed).
  • Drawer (bottom): the Log and the Summary table of the last run; the arrow opens and closes it.
  • Load and Save (top right): read or write the page's configuration as JSON. A configuration saved here runs unchanged with seecat.run.

Running

Run checks every option first and lists all problems at once (an empty required folder, a value out of range). The pipeline then runs in a separate MATLAB process: the window stays usable, the log streams into the drawer, and Stop ends the process (units that finished keep their outputs; the unit that was interrupted resumes next time). When the run ends, the Summary tab of the drawer shows the run's table (one row per unit, as in reports/<pipeline>_<time>_summary.tsv); each unit's own log is in logs/<pipeline>_<time>/.

Workflow

DICOM→DICOM to BIDS→BIDS dataset→Data check→Preprocessing→QC reports→Seed FC / Degree / Gradients→Harmonize (multi-site)→Statistics→Viewer

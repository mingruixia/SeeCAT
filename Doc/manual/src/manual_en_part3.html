Worked examples

This chapter runs a complete study and reports what SeeCAT produced, with the real numbers. Every figure in this manual comes from these runs. The script that ran them is in section 8.2; the configurations can also be loaded into the window with Load.

The example dataset

A public test subset of a multi-site depression study: 30 subjects from three sites (CSU, PKU, SCU), five healthy controls (HC) and five patients with major depression (MDD) at each site. Every subject has one T1-weighted image and one resting-state run (TR 2 s). The three per-site folders were merged into one BIDS dataset with a participants.tsv:

participant_id   site   group   age   sex
sub-CSUHC0001    CSU    HC      28    M
sub-CSUHC0002    CSU    HC      34    M
…
Simulated covariates. Age and sex in this table were generated at random for the demonstration. They are fine as covariates, but no real effect of age or sex is in the data: a significant age effect would be a false positive.

All runs used n_workers = 'auto' on a 32-core workstation with about 200 GB of free memory. The outputs go to manual_run/derivatives/seecat.

Example A: seed connectivity of the default-mode network

From BIDS to a group map of posterior cingulate (PCC) connectivity, and a comparison of the two groups.

A1. Check the data

On Data check, choose the BIDS folder and press Scan. The table lists 30 runs, one per subject, with their volumes and TR (section 6.2). Nothing is missing, so preprocessing can start.

A2. Preprocess

On Preprocessing: BIDS folder bids2, Output folder manual_run/derivatives/seecat, tick VBM maps (for Example B), Parallel workers auto; all other options at their defaults. Press Run.

A5. Harmonize

On Harmonize: Map PCC, Statistic z, Site column site, Method combat, Covariates kept group, sex, age.

[harmonizeComBat_PCCz_3821b739] voxels with a site effect (p < 0.05): 9.9% before, 0.1% after

Before harmonisation, 9.9% of grey-matter voxels had a site effect, about twice the 5% expected by chance. After ComBat, 0.1% did. The new maps are named desc-PCCComBat. With sites this small, SeeCAT also logs the small-site warning of section 6.9. Here we keep ComBat for the FC maps; Example B shows when this matters.

Example B: grey-matter volume and age (VBM)

Because VBM maps was ticked in A2, every T1w already has modulated grey-matter maps in MNI space (1.5 mm), smoothed with 8 mm:

sub-SCUHC0001_space-IXI549Space_res-1p5_label-GM_desc-modulatedSm8_probseg.nii

Total intracranial volume per subject is in reports/anat_volumes.tsv. Statistics and Harmonize read it automatically as the column tiv_ml. The QC exclusions are for fMRI runs, so all 30 T1w images are used here.

[VBMage] 30 maps, 414177 voxels in the analysis mask
[VBMage] df 24.00; FWHM [11.43 11.81 11.25] mm; resels 797.0
[VBMage] agepos, cluster_fwe: height 3.467, 0 cluster(s) / 0 voxel(s) survive

The site column is text, so it enters the model as two indicator columns. With intercept, age, sex, TIV and site, that leaves 30 − 6 = 24 degrees of freedom. Since the ages are random, no effect is the correct result.

B2. Why not ComBat here

Site differences in VBM are large: in 49.8% of grey-matter voxels before harmonisation (0.2% after ComBat with group, sex, age and TIV kept). It seems natural to harmonise first. We ran the same regression after each choice:

MapsSite in the modelClusters for age (cluster FWE)
unharmonisedas a covariate0
ComBat (combat)no3
ComBat (combat)as a covariate2
location only (combat_mean)no0
linear regression (lm)no0

The age effect is not real, so the ComBat clusters are false positives. ComBat rescales each site's residual variance using only ten subjects per site. That makes the harmonised data look less variable than they are, and tests of the kept covariates become too liberal (Nygaard et al. 2016). Methods that only remove site means do not have this problem. With fewer than about 20 subjects per site:

  • use combat_mean or lm, or keep the maps unharmonised with site as a covariate;
  • compare any ComBat result with the unharmonised one before reporting it.

SeeCAT writes this warning in the Harmonize log and report.

Example C: degree centrality and gradients

C1. Degree

Degree with its defaults: grey-matter mask, positive correlations above r = 0.2, binary and weighted degree, also as z-scored maps, smoothed with 6 mm.

Parallel workers (auto): about 3.9 GB per worker (2.9 GB task + 1 GB worker), …: 26 worker(s)
Done: 26 ok, 0 skipped, 0 failed.

The 26 runs took about 2 minutes. Each run gets four maps, each as raw values and as z:

…_desc-degPosBinR0p2_stat-z_connectivity.nii.gz        binary, unsmoothed
…_desc-degPosWeiR0p2Sm6_stat-z_connectivity.nii.gz     weighted, smoothed: the usual choice for statistics

Harmonising degPosWeiR0p2Sm6 z (with group, sex and age kept) reduced voxels with a site effect from 17.2% to 0.0%. Degree is more site-dependent than seed FC here, probably because it summarises the whole connectivity distribution, which depends on noise and smoothness.

C2. Gradients

Gradients with the defaults: Nodes voxels with Node size 4 mm (the unit is named gradientsVox4), 10 components with 3 maps written, Alignment group.

Parallel workers (auto): about 8.2 GB per worker (7.2 GB task + 1 GB worker), 7.7 GB kept by the main MATLAB,
    187.4 GB free: 18 worker(s) (32 cores, 26 task(s))
[gradientsVox4] 26 run(s), 21972 nodes (Vox4); about 7.2 GB of memory per run being computed
[gradientsVox4] node series done; 19564 of 21972 nodes have data in every run
[gradientsVox4] gradients of 26 run(s) in 413 s (15 worker(s))
[gradientsVox4] finished (472.0 s)

Each run needs a 21972 × 21972 connectivity matrix, so memory, not cores, set the number of workers (18). The reference is the gradient of the group-mean matrix. Each run is aligned to it, a new reference is formed from the mean of the aligned runs, and this repeats until the reference no longer changes.

{{IMG viewer_gradient.png | The group reference of gradient 1 (group/gradientsVox4/gradientsVox4_desc-grad1_reference). It runs from visual and sensorimotor cortex (blue) to the default-mode network (red), the principal gradient of Margulies et al. (2016).}}

group/gradientsVox4/gradientsVox4_lambdas.tsv gives, per run:

  • the eigenvalues;
  • the variance explained by gradient 1: 0.18 to 0.31, median 0.24;
  • the correlation of the run's aligned gradient 1 with the reference: 0.43 to 0.69, median 0.58.

A run with a much lower correlation than the others deserves a look at its QC report. The per-run maps (desc-grad1Vox4 … grad3Vox4) can be harmonised and tested like any other map.
